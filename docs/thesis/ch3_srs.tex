\section{Use Cases}
\label{sec:use-cases}

\subsection{UC-01: Complete Virtual Try-On Session}

\textbf{Primary Actor:} Shopper

\textbf{Preconditions:} Kiosk application is running; backend server is accessible; catalog is loaded.

\textbf{Main Flow:}
\begin{enumerate}[leftmargin=*]
  \item User selects gender (men or women).
  \item User browses catalog and selects a garment.
  \item User views garment preview on the mirror stage.
  \item User proceeds to camera step; webcam captures a still frame.
  \item Frontend sends try-on request with \texttt{clothId} and \texttt{webcamImage}.
  \item Backend returns instant Sharp preview (HTTP 202) or final image (HTTP 200).
  \item Frontend polls prediction status until Replicate succeeds.
  \item Validated AI image replaces preview via crossfade animation.
  \item User views final try-on result.
  \item User may start a new outfit session.
\end{enumerate}

\textbf{Alternate Flows:}
\begin{itemize}[leftmargin=*]
  \item \textbf{3a.} Replicate is unavailable: backend uses exhibition fallback chain; user sees composite result.
  \item \textbf{3b.} Replicate returns invalid output: validator rejects output; fallback chain produces composite.
  \item \textbf{3c.} User clicks ``New Outfit'' during polling: stale prediction is dropped; session resets.
\end{itemize}

\subsection{UC-02: Browse Catalog Without Try-On}

\textbf{Primary Actor:} Shopper

\textbf{Main Flow:}
\begin{enumerate}[leftmargin=*]
  \item User selects gender.
  \item User scrolls through garment grid filtered by category tabs.
  \item User selects a garment to view preview.
\end{enumerate}

\subsection{UC-03: AI Stylist Consultation}

\textbf{Primary Actor:} Shopper

\textbf{Main Flow:}
\begin{enumerate}[leftmargin=*]
  \item User opens the floating stylist assistant.
  \item User types a natural language query (e.g., ``Suggest a casual summer outfit'').
  \item Backend forwards query to Ollama LLM.
  \item Stylist response is displayed in the assistant panel.
\end{enumerate}

\section{System Constraints}
\label{sec:constraints}

\begin{itemize}[leftmargin=*]
  \item \textbf{Hardware:} Standard PC with webcam, display (kiosk), and network connectivity.
  \item \textbf{Software:} Node.js 18+, MongoDB 6+, modern Chromium-based browser.
  \item \textbf{Network:} Internet access required for Replicate cloud inference.
  \item \textbf{API Keys:} Replicate API token required for live AI try-on; HuggingFace token for CATVTON.
  \item \textbf{Browser:} WebRTC support required for webcam capture.
\end{itemize}

\section{External Interface Requirements}
\label{sec:interfaces}

\subsection{User Interface}

The kiosk UI follows a step-based flow: gender selection $\rightarrow$ catalog browsing $\rightarrow$ garment preview $\rightarrow$ camera capture $\rightarrow$ try-on result. The interface is optimized for touch interaction on large displays with minimal text input.

\subsection{API Interface}

RESTful JSON APIs exposed by the Express backend:

\begin{itemize}[leftmargin=*]
  \item \texttt{POST /api/tryon} --- Submit try-on request
  \item \texttt{GET /api/tryon/status/:predictionId} --- Poll prediction status
  \item \texttt{GET /api/catalog/items} --- Fetch catalog with filters
  \item \texttt{POST /api/ai/stylist} --- AI stylist query
  \item \texttt{GET /api/replicate/health-test} --- Replicate connectivity probe
\end{itemize}

\subsection{Hardware Interface}

\begin{itemize}[leftmargin=*]
  \item Webcam via browser MediaDevices API (WebRTC).
  \item Touch display for kiosk interaction.
  \item Network interface for backend and Replicate API communication.
\end{itemize}
